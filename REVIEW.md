# REVIEW.md

## Starter Code Review & Defects Analysis

Every helper and starter endpoint in `app/main.py` was inspected and tested against `openapi.yaml`, `DATA_MODEL.md`, and `PROBLEM_STATEMENT.docx`. The defects found, concrete failure cases, and their fixes are detailed below:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | Grace period boundary defect: `minutes > 10` checks floor minutes instead of elapsed seconds. A punch-in at 09:40:01 for a 09:30 shift has elapsed 601 seconds; `int(601/60) = 10`, so `10 > 10` evaluates to False and returns 0 instead of 10. | Calling `compute_late_minutes(punch_in="09:40:01", shift_start="09:30")` returns 0 instead of 10. | Replaced condition with `diff_sec > 600`. If strictly greater than 600 seconds, late minutes are calculated as `diff_sec // 60` from shift start. |
| 2 | `compute_late_minutes` (lines 33–37) | Timezone and overnight shift defect: Used `punch_in.replace(hour=h, minute=m)` on UTC/naive datetime without converting to IST or handling overnight shifts (22:00–06:00). For punch-in at 00:30 IST, setting start on the same date creates a future start time and negative delta. | Overnight shift 22:00–06:00, punch-in at 00:30 IST on next calendar day yielded negative difference. | Converted instants to IST, determined the R1 attendance date (previous calendar day if punch-in before `shift_end`), and constructed shift start datetime on the correct attendance date. |
| 3 | `compute_work_hours` (lines 40–41) | Banker's rounding defect: Built-in Python `round()` uses round-half-to-even and floating point arithmetic instead of Decimal half-up rounding (R4). Also failed to truncate instants to whole seconds. | Submitting durations where fractional hours end in .005 or boundary values (e.g. 2.675 hours) yields 2.67 with `round()` instead of 2.68. | Truncated instants to whole seconds (R1) and computed work hours using `Decimal(diff_sec) / Decimal(3600)` quantized with `ROUND_HALF_UP` to two decimal places. |
| 4 | `compute_overtime` (lines 44–48) | Missing 30-minute threshold defect: Returned all minutes past shift end (`diff / 60`), violating R3 which requires overtime to be recorded only when at least 30 minutes; otherwise 0. | Punch-out at 18:35 for 18:30 shift end returned 5 instead of 0. | Added threshold check `return minutes if minutes >= 30 else 0`. |
| 5 | `compute_overtime` (lines 44–48) | Overnight shift end date defect: Associated `shift_end` with `date_str` for all shifts. For overnight shifts (22:00–06:00), `shift_end` falls on `date + 1 day`. Attaching it to `date_str` placed shift end 16 hours prior to shift start. | Overnight punch-out at 06:40 IST on next day gave thousands of overtime minutes. | Added `is_shift_overnight` check to project `shift_end` to `date + 1 day` when `shift_end <= shift_start`. |
| 6 | `compute_overtime` (lines 44–48) | Offset-naive vs offset-aware datetime subtraction: `end` was created with `tzinfo=IST` while `punch_out` from MongoDB was naive UTC, causing unhandled `TypeError`. | Calling with naive UTC `punch_out` raised `TypeError: can't subtract offset-naive and offset-aware datetimes` (HTTP 500). | Ensured all instant comparisons use aware UTC datetimes converted to IST before subtraction. |
| 7 | `GET /health` (lines 72–74) | Fake health probe: Returned static `{"status": "ok"}` without verifying MongoDB connectivity. Contract requires 200 only if MongoDB answers a ping, else 503. | Stopping MongoDB resulted in `/health` returning 200 OK instead of 503 Service Unavailable. | Implemented `client.admin.command("ping")` and index check; on failure, raises HTTP 503 with `{"detail": "Database unavailable"}`. |
| 8 | `POST /employees` (lines 78–85) | Concurrency race condition & missing validation: Used `find_one` before insert; concurrent requests with identical `emp_code` both pass the check. Missing regex validation for `emp_code`, email, and did not reject `shift_start == shift_end`. | Concurrent POST requests with duplicate `emp_code` created duplicates; payload with `shift_start: "09:30"` and `shift_end: "09:30"` was accepted with 201 instead of 422. | Enforced unique index on `employees.emp_code`, handled `DuplicateKeyError` to return HTTP 409, added Pydantic validators rejecting equal shifts and invalid codes with HTTP 422. |
| 9 | `POST /employees` (lines 78–85) | Serialization defect: Stored local naive `datetime.now()` and returned ISO string instead of integer epoch milliseconds (`EpochMillis`). | `created_at` in response was an ISO string, violating OpenAPI schema contract. | Stored UTC BSON datetime and serialized to integer epoch milliseconds truncated to whole seconds. |
| 10 | `GET /employees` (lines 89–96) | Pagination skip defect: `skip = page * page_size` skipped the first page when `page=1` (skipped records 1–20). Total count also ignored the `department` filter. | Requesting `page=1, page_size=20` returned items 21–40; filtering by department returned total of the entire collection. | Corrected skip offset to `(page - 1) * page_size` and filtered total count with `count_documents(q)`. Added `.sort("emp_code", ASCENDING)`. |
| 11 | `POST /attendance/punch-in` (lines 100–121) | Unhandled missing employee (HTTP 500): Directly accessed `emp["shift_start"]` without verifying `emp` was not None, resulting in `TypeError`. | Submitting an unknown `emp_code` produced HTTP 500 Internal Server Error instead of HTTP 404. | Added explicit check `if not emp: raise HTTPException(404, "Unknown employee")`. |
| 12 | `POST /attendance/punch-in` (lines 100–121) | Check-then-insert race condition: Used `find_one` before insert; concurrent punch-in requests for same employee and date could both insert records. | Sending two simultaneous punch-ins resulted in duplicate records or inconsistent states. | Created unique compound index on `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409 atomically. |
| 13 | `POST /attendance/punch-in` (lines 100–121) | Attendance date timezone defect: Used `ts.date().isoformat()` using server local time without IST timezone conversion or overnight shift resolution. | Punch-in at 01:00 IST on overnight shift (22:00–06:00) recorded current date instead of shift start date (previous calendar day). | Implemented R1 attendance date logic with IST conversion and overnight shift previous-day resolution. |
| 14 | `POST /attendance/punch-in` (lines 100–121) | Input validation and schema defect: Allowed non-presence statuses (e.g. ABSENT/LEAVE) and returned non-contract `id` field from `inserted_id`. | Passing `status: "LEAVE"` or `"INVALID"` succeeded; response contained `id` property not in OpenAPI schema. | Restricted status to `Literal["PRESENT", "WFH", "ON_DUTY"]`, validated integer epoch milliseconds, and formatted output strictly according to `AttendanceRecord`. |
| 15 | `GET /attendance` (lines 125–150) | In-memory sort and scale bottleneck: Loaded entire collection into memory with `list(db.attendance_logs.find(q))` and sorted in Python. Injected non-contract `id` field. | High latency and memory exhaustion on large collections (~100k docs); response contained extra `id` field. | Moved sorting and pagination to MongoDB cursor (`.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`), removed extra `id` field, and validated `date_from <= date_to`. |
| 16 | Startup & Configuration | Missing startup indexes and environment variable precedence: Zero indexes were created at startup; `load_dotenv()` did not enforce that process environment variables override `.env`. | Application started without database indexes; setting `MONGO_URI` in shell environment could be overridden by `.env`. | Implemented idempotent index creation at startup in FastAPI lifespan; set `load_dotenv(override=False)`. |

---

## Important Items Examined and Found Correct

1. **IST Timezone Definition:**
   `timezone(timedelta(hours=5, minutes=30))` correctly captures Indian Standard Time (UTC+05:30) without relying on external system tzdata packages.

2. **Domain Status Enum Definitions:**
   The status values (`PRESENT`, `WFH`, `ON_DUTY`, `ABSENT`, `LEAVE`) defined in the domain model correctly separate presence statuses from non-presence statuses.

3. **FastAPI & PyMongo Integration:**
   FastAPI routing and dependency injection patterns provide the proper structure for route handling, and PyMongo with `tz_aware=True` correctly preserves UTC timestamps across BSON boundaries.
